## 📖 এক নজরে

| আগে যে সমস্যা ছিল | এখন কী করা হয় |
|---|---|
| Whisper ৩০ সেকেন্ডের সীমায় **শব্দের মাঝখানে** কাটত (`XYZ` → `XY` + `Z`) | শুধু **৩০০ ms+ নীরবতার মাঝখানে** কাটা হয় (১৮–২৮s chunk), সীমানায় সন্দেহ হলে ছোট উইন্ডো আবার ডিকোড (seam repair) |
| পাংচুয়েশন হারিয়ে যেত, বাক্য ভাঙত | আগের লেখার শেষ ~২২০ অক্ষর **rolling prompt** হিসেবে যায় → বাক্যের ধারাবাহিকতা ও punctuation ঠিক থাকে |
| রোবটিক কণ্ঠ | **বিল্ট-ইন বাংলা neural ভয়েস** (`bn-BD-PradeepNeural`, পুরুষ) — কোনো সেটআপ লাগে না; tempo কখনো ১.২৫-এর বেশি নয় |
| দুই কণ্ঠ একসাথে বাজত | **Non-overlap sync solver** — প্রতিটি ক্লিপের জন্য আলাদা সময়-উইন্ডো; কঠোরভাবে কোনো overlap নেই |
| অনুবাদ সময়ের চেয়ে লম্বা/ছোট হতো | Gemini-কে প্রতিটি লাইনের **সময়ের বাজেট** জানানো হয়; না আঁটলে লাইনটি ছোট করে লেখানো হয় |
| ১০ মিনিটের ভিডিওতে অনেক সময় লাগত | অনুবাদ (নেটওয়ার্ক) ও TTS (GPU) **একসাথে** চলে; গতি বাজেট রাখতে একটি Speed Governor আছে → **২–৩ মিনিট** |
| টার্মিনালে আবার key/token চাইত, সেল রান করলে প্রম্পট আসত | **কোনো প্রম্পট নেই** — key নোটবুকের সেলেই পেস্ট করা হয়; HF token না দিলে অ্যাপ ধরে নেয় ক্লোনিং দরকার নেই এবং চুপচাপ বিল্ট-ইন ভয়েসে এগিয়ে যায় |
| অডিও extract করার সময় ঝুলে যেত, একই লগ বারবার আসত | ffmpeg-এ **`-nostdin`** + stdin বন্ধ (ব্লক হওয়ার মূল কারণ), **লাইভ শতাংশ লগ**, আর অগ্রগতি বন্ধ হলে **stall detector** — নিজেই থেমে software decoding-এ নামে বা স্পষ্ট error দেয় |
| Gemini key ভুলে গেলে অনেকক্ষণ পরে ফেইল করত | key না থাকলে **শুরুতেই** পরিষ্কার error (`exit=2`), কিছুই প্রসেস শুরু হয় না |

## 🎤 কণ্ঠ: ডিফল্টে যা হয়

`tts.engine: auto` (ডিফল্ট) মানে — **আপনাকে কিছু বেছে নিতে বা দিতে হয় না**:

| পরিস্থিতি | কী হবে |
|---|---|
| ইনপুট ফোল্ডারে কণ্ঠের নমুনা নেই | **বিল্ট-ইন `bn-BD` neural ভয়েস** (Pradeep, পুরুষ) — সঙ্গে সঙ্গে কাজ শুরু |
| ইনপুট ফোল্ডারে ৫s+ বাংলা কথার audio আছে | নিজে থেকেই **কণ্ঠ ক্লোনিং (IndicF5)** চেষ্টা করবে |
| ক্লোনিং চালু করা গেল না (HF অনুমতি/VRAM/ডিপেন্ডেন্সি) | স্পষ্ট মেসেজ দিয়ে বিল্ট-ইন ভয়েসে ফিরে আসবে — ভিডিও নষ্ট হবে না |

বিল্ট-ইন ভয়েস নির্ধারণ হয় `config.yaml`-এর `tts.gender` দিয়ে —
`male` (**ডিফল্ট**, `bn-BD-PradeepNeural`) / `female` (`bn-BD-NabanitaNeural`)
/ `custom` (তখন `tts.voice`-এ যা লেখা থাকবে)। `gender`-ই প্রধান: পুরোনো
`config.yaml`-এ নারী ভয়েস লেখা থাকলেও `male` থাকলে **পুরুষ কণ্ঠই** ব্যবহার
হবে। তাই কণ্ঠ বদলাতে চাইলে `gender` বদলান, শুধু `voice` নয়।

## ⚙️ ভিতরে কীভাবে কাজ করে

পুরো যাত্রা ৭টি ধাপে — প্রতিটির সময় লগে ও রিপোর্টে দেখানো হয়।

```
ভিডিও ─► [1] অডিও extract (16 kHz mono)
       ─► [2] ভয়েস প্রোফাইল (ঐচ্ছিক — নমুনা ও HF টোকেন থাকলে)
       ─► [3] STT (silence-aware chunk + rolling prompt + seam repair)
       ─► [4] অনুবাদ (Gemini, duration-aware) + TTS (ভয়েস)
       ─► [5] Sync (non-overlap উইন্ডো, tempo ≤ 1.25)
       ─► [6] Mux (ffmpeg) ─► [7] SRT
```

### ১) শব্দের মাঝখানে কাটা আর হবে না

Whisper একবারে ৩০ সেকেন্ডের বেশি দেখতে পারে না, তাই কাটা বাধ্যতামূলক। আগে
faster-whisper নিজেই জোর করে কেটে দিত — ফলে একটি শব্দ দুই টুকরো হয়ে যেত।
এখন:

* Silero VAD (না থাকলে RMS energy) দিয়ে **কথার অঞ্চল** বের করা হয়,
* অঞ্চলগুলো ১৮–২৮ সেকেন্ডের chunk-এ জোড়া লাগানো হয় — কাটা পড়ে **দুই অঞ্চলের
  মাঝের নীরবতায়** (অন্তত ৩০০ ms),
* একটানা ৩০s কথা বললেই কেবল জোর করে কাটা হয়, আর সেই chunk-এ `forced` ফ্ল্যাগ
  থাকে → সীমানার ±২.৫s আবার ডিকোড করে শব্দ ঠিক করা হয় (seam repair)।

### ১খ) "কাজ করতে করতে ঝুলে যায়" — আর হবে না

পুরোনো সমস্যা: অডিও extract করার সময় ffmpeg চুপচাপ আটকে যেত, লগ একই
লাইন বারবার ছাপত, আর কিছুই এগোত না। কারণ ও সমাধান:

* ffmpeg-এর **stdin খোলা** থাকত — নোটবুকে (`!python main.py`) সেটি TTY/pipe
  হওয়ায় ffmpeg কী-ইনপুটের অপেক্ষায় ব্লক করে বসত। এখন সব ffmpeg কলে
  **`-nostdin` + stdin=DEVNULL**, তাই ব্লক হওয়া অসম্ভব।
* **`-hwaccel auto`** বাদ দেওয়া হয়েছে (`-vn` দিয়ে ভিডিও stream ফেলাই দিচ্ছি,
  GPU decode-এ কোনো লাভ নেই, শুধু আটকে যাওয়ার ঝুঁকি) — দরকার হলে
  `runtime.use_hwaccel` দিয়ে চালু করা যায়, আর ঝুললে নিজেই software-এ নামে।
* **লাইভ অগ্রগতি**: `অডিও extract: 45% (04:30 / 10:00) — চলছে…` — ১০ সেকেন্ড
  পরপর, কেবল শতাংশ বদলালে। মোট অডিও decode আর muxing-এও একই।
* **Stall detector**: `runtime.extract_stall_seconds` (ডিফল্ট ৯০) সেকেন্ড
  কোনো অগ্রগতি না এলে প্রসেস kill হয় → পরের পথ চেষ্টা → শেষে স্পষ্ট error।
  অর্থাৎ অনন্তকাল অপেক্ষা নয়।
* **STT-তেও অগ্রগতি**: `STT 3/12 — 01:00–01:28` প্রতিটি chunk-এ, তাই মডেল
  ডাউনলোড/ডিকোডের সময়ও বোঝা যায় কাজ এগোচ্ছে কি না।

### ২) পাংচুয়েশন ও বাক্যের ধারাবাহিকতা

প্রতিটি chunk ডিকোড করার সময় আগের টেক্সটের শেষ ~২২০ অক্ষর
`initial_prompt` হিসেবে দেওয়া হয় — Whisper বাক্যের মাঝ থেকে শুরু করে না,
তাই যুক্তি/পাংচুয়েশন ঠিক থাকে। এরপর শব্দগুলোকে বাক্যে সাজানো হয়
(সর্বোচ্চ ~১২–১৫ শব্দ, এক আইডিয়া এক segment)।

### ২খ) পুরো বাক্য = একটা clip (কথার মাঝপথে থামা নেই)

Whisper-এর segment সবসময় পুরো বাক্য নয় — ৩০ সেকেন্ডের সীমা, বিরতি বা
শব্দ-সংখ্যার কারণে বাক্য মাঝপথে ভাগ হয়ে যায়। আগে প্রতিটি segment আলাদা
TTS ক্লিপ হতো, তাই কণ্ঠ বারবার থেমে আবার শুরু করত:

```
"…তার বিনিময় আমি একজন ভাগ্যবান সাবস্ক্রাইবারকে"  ← clip ১ (থামল)
"একটি করে স্টার পাস গিভঅ্যাওয়েতে হবে…"        ← clip ২ (আবার শুরু)
```

এখন `prosody.py` পাশাপাশি segment-গুলোকে **speech unit**-এ জোড়া লাগায় —
মাঝের বিরতি ≤০.৬s হলে, আগের টুকরো বাক্য শেষ না করলে, এবং unit ≤১২s/২৪০
অক্ষর হলে। অনুবাদ, TTS, sync সবই unit ধরে চলে, তাই একটি বাক্য একটি ক্লিপ।
unit-টি নিজের আসল সময়-উইন্ডোতেই বসে (ভেতরের ছোট বিরতিসহ), ফলে ঠোঁটের সাথে
মিলও আগের মতোই থাকে; আর সাবটাইটেল unit-এর বাংলা থেকে বাক্য ধরে ভাগ হয়।

### ২গ) কণ্ঠের গতি আগে মাপা হয় (তাড়াহুড়ো বন্ধ)

আগে ধরা হতো বাংলা কণ্ঠ সেকেন্ডে ১৪ অক্ষর বলে; বাস্তবে প্রায় ১২। ফলে
অনুবাদ দৈর্ঘ্যে বেশি হয়ে যেত, sync-এ ১.২৫× দ্রুত করতে হতো (শেষটা কেটেও
যেত)। এখন ভিডিওর শুরুতে **আসল কণ্ঠ দিয়ে ২টি বাক্য বলে প্রকৃত গতি মাপা হয়**
(`speech_rate.py`, খরচ ~১–২ সেকেন্ড), সেই হারেই Gemini-কে সময়-বাজেট দেওয়া
হয়, আর লগে দেখা যায়:

```
🎚️ কণ্ঠের প্রকৃত গতি মাপা হলো: 11.8 অক্ষর/সেকেন্ড
```

### ২ঘ) বাক্যের পরে লম্বা ফাঁক নেই (ধারাবাহিক কথা)

সমস্যা: “এক লাইন বলে বলার পরে অনেকক্ষণ গ্যাপ থাকে, তারপর বাকিটা বলে।”
আসল ফাইল মেপে দেখা গেছে মোট ৫২.৫ সেকেন্ড নীরবতা; তার বেশিরভাগই দুটি কারণে:

1. **TTS ক্লিপের দুই প্রান্তের নীরবতা** — edge-tts প্রতিটি ক্লিপে ~০.৫–০.৮
   সেকেন্ড নীরবতা জুড়ে দেয়; আগে সেটুকুও ক্লিপের সাথে বসানো হতো, তাই প্রতিটি
   বাক্যের পরেই অযথা বিরতি, আর গতি হিসাবও ভুল হতো।
   **সমাধান:** এখন প্রতিটি ক্লিপ তৈরি হওয়ার সাথে সাথে দুই প্রান্ত ছাঁটা হয়
   (`tts.trim_silence`, ২৫ ms প্যাড রেখে) এবং দৈর্ঘ্য আবার মাপা হয়।
2. **স্লটের চেয়ে ছোট বাংলা লাইন** — অনুবাদ ছোট হলে স্লটের বাকি অংশ নীরব থাকত।
   **সমাধান:** (ক) ছোট ক্লিপকে স্লট ভরাতে সর্বোচ্চ ১২% পর্যন্ত **ধীর** করা হয়
   (`sync.fill_extension`) — কণ্ঠ স্বাভাবিক শোনায়, আর (খ) ফাঁক ০.৯ সেকেন্ডের
   বেশি হলে Gemini দিয়ে শুধু **সেই লাইনগুলো ভরাট করে** আবার লেখানো হয়
   (`translation.expand_pass`) — নতুন তথ্য যোগ না করে স্বাভাবিক কথ্য শব্দ
   (“তো”, “আসলে”, “দেখুন”, ইত্যাদি) দিয়ে কথা লম্বা করা হয়, তারপর শুধু ওই
   ক্লিপগুলোরই আবার TTS হয়। ফলে পুরো ভিডিও নতুন করে অনুবাদ হয় না (সময় বাঁচে)।
3. **অনূদিত হয়নি এমন লাইন** — কোনো ইংরেজি বাক্য অনুবাদে বাদ পড়লে পুরো স্লটই
   নীরব থাকত। এখন প্রতি লাইনে `c` (কত অক্ষর বসবে) টার্গেট দেওয়া হয় এবং
   ডিকোড-ব্যর্থতা শুধু ওই লাইনেই সীমাবদ্ধ থাকে; বাদ পড়া লাইনের সংখ্যা লগে
   স্পষ্ট দেখানো হয়।

লগে এখন সরাসরি সংখ্যা দেখা যায়:

```
🕳️ 7টি লাইনের পরে বড় ফাঁক (≥0.9s) — অনুবাদ আরও ভরাট করে লেখানো হচ্ছে…
✅ 7টি লাইন ভরাট করে আবার কণ্ঠ দেওয়া হলো (ফাঁক কমল)।
চূড়ান্ত Bangla অডিও: … | 654.6s | 66 ক্লিপ | সর্বোচ্চ tempo 1.18
(জোরালো stretch 3, স্লট ভরাতে ধীর 41) | নীরবতা 9.4s (1.4%) | ওভারল্যাপ ০
```

সেই সাথে সংখ্যার দৈর্ঘ্যও এখন কথার হিসেবে ধরা হয় — "১২৫" লেখায় ৩ অক্ষর,
বলায় "একশ পঁচিশ" (৯ অক্ষর); আগে এই পার্থক্য সময়ের হিসাব থেকে বাদ পড়ে
সংখ্যাভরা লাইনগুলো লম্বা হয়ে যেত।

আপনার পাঠানো লগে (৯৭৯৯ অক্ষর / ৬৫৪ সেকেন্ড, ২১৩ ক্লিপ) ১৭০টি ক্লিপে
`stretch` লাগছিল। উপরের সংশোধনের পর একই ভিডিওতে আনুমানিক হিসাব দাঁড়ায় —
প্রয়োজনীয় tempo-র median ১.২৩× → ১.০৭×, আর ১.২৫× ছাড়ানো ক্লিপ ৬২টি → ০টি।

### ২ঙ) নাম-শব্দের নির্ভুলতা (hotwords)

গেম/ব্র্যান্ড/খেলোয়াড়ের নাম Whisper প্রায়ই ভুল লেখে ("star pass" →
"star 3 pestles")। `hotwords`-এ ভিডিওর শব্দগুলো দিলে Whisper সেগুলো সহজে
চিনবে, আর Gemini-ও একই বানান রাখবে:

```yaml
stt:
  hotwords: "FC Mobile, Ballon d'Or, OVR, star pass, Yashin"
```

নোটবুকের ধাপ ৭-এ `HOTWORDS` বসালেই হবে (কোনো টার্মিনাল কমান্ড লাগে না)।

### ৩) কণ্ঠ

* ডিফল্ট: **edge-tts**-এর `bn-BD-PradeepNeural` (**পুরুষ** কণ্ঠ) — কোনো
  নমুনা/টোকেন/লাইসেন্স লাগে না, ইন্টারনেট থাকলেই চলে (৫টি ক্লিপ একসাথে,
  retry সহ)। নারী কণ্ঠ চাইলে `--voice bn-BD-NabanitaNeural`।
* ঐচ্ছিক: ইনপুট ফোল্ডারে নমুনা থাকলে **IndicF5** দিয়ে zero-shot ভয়েস
  ক্লোনিং। নমুনা থেকে VAD দিয়ে সেরা একটানা কথা-উইন্ডো নেওয়া হয়, ffmpeg
  high-pass + loudnorm করা হয়, `ref_text` নিজেই বের করা হয় এবং ফলাফল ক্যাশ
  হয় — তাই পরের রানে সঙ্গে সঙ্গে প্রস্তুত।

### ৪) অনুবাদ সময় জানে

Gemini-কে প্রতিটি লাইনের সাথে তার **সময়সীমা (সেকেন্ড, `d`)** এবং ওই
সময়ে কত অক্ষর আঁটে (`c` — মাপা গতি থেকে) দুটোই দেওয়া হয়, আর নির্দেশ থাকে
সময়ের মধ্যে থেকে **বাক্য শেষ করে** লিখতে হবে।

#### ৪ক) Gemini ভুল ফরম্যাটে উত্তর দিলে — অপেক্ষা নেই, হারানো লাইনও নেই

আগে ফরম্যাট ভুল হলে অপেক্ষা ৪ → ৮ → ১৬ … সেকেন্ড করে বাড়ত এবং পুরো
২৫-লাইনের ব্যাচ আবার চাওয়া হতো (ফলে ৩–৪ মিনিট নষ্ট)। এখন:

1. **অপেক্ষা সর্বোচ্চ ২ সেকেন্ড** — ফরম্যাট ভুলে তো প্রায় নেই (০–০.২s),
   সঙ্গে সঙ্গে আবার request যায় (নেটওয়ার্ক/429-এ ০.৫–২s)। ফরম্যাট ভুলের
   retry রেট-লিমিটের স্লটও খরচ করে না (আগে প্রতিবার ৪s করে "ডাবল" অপেক্ষা হতো)।
2. **উত্তর সহনশীলভাবে পড়া হয়** — কোড-ফেন্স, আগে/পরে বাড়তি লেখা,
   `{"translations":…}` বাদ দিয়ে শুধু লিস্ট, `{"bn": …}` অবজেক্ট, এমনকি
   নম্বরযুক্ত লাইন (`1. বাংলা`) — সবই বোঝা যায়।
3. **উত্তর কেটে গেলে (MAX_TOKENS)** শুরুর সম্পূর্ণ লাইনগুলো রাখা হয়, শুধু
   **বাকি লাইনগুলোর** জন্য সঙ্গে সঙ্গে নতুন request যায় — পুরো ব্যাচ নয়।
4. **ফরম্যাট সহজ করা হয় ধাপে ধাপে** — `schema JSON → সাধারণ JSON →
   নম্বরযুক্ত লাইন`; মডেল/SDK কোনো অপশন না চিনলে সেটি নিজেই বাদ দিয়ে
   আবার চেষ্টা করে।
5. **output budget ইনপুটের সাথে বাড়ে** (বাংলা টোকেন-ভারী, ছোট বাজেটেই
   উত্তর কেটে যেত) এবং উত্তর **মাঝপথে কাটা ঠেকাতে খরচ কমাতে thinking বন্ধ**।
6. তবু একটি লাইন না পারলে শুধু **সেই লাইনটি বাদ** যায় — পুরো ভিডিও নষ্ট হয় না।
 তারপরও কোনো লাইন ১.২৫× গতিতেও না আঁটলে
সেটি আরও সংক্ষেপে লেখানো হয়। তাই `atempo` খুব কম ক্ষেত্রে লাগে — কণ্ঠ
স্বাভাবিক শোনায়।

### ৫) কোনো overlap নেই

`sync_engine` প্রতিটি segment/speech-unit-এর জন্য আলাদা উইন্ডো বানায়:

```
উইন্ডো শেষ = min(পরের segment শুরুর আগে (৮০ ms ফাঁক), নিজের কথা + সর্বোচ্চ ২৫০ ms ধার)
```

ক্লিপ উইন্ডোর চেয়ে লম্বা হলে শেষে ছেঁটে fade দেওয়া হয় — **দুই কণ্ঠ একসাথে
বাজা অসম্ভব**। এরপর সব ক্লিপের RMS লেভেল মিলিয়ে দেওয়া হয়, যাতে এক বাক্য
উঁচু আরেক বাক্য নিচু না শোনায়।

### ৬) গতি

* অনুবাদ (নেটওয়ার্ক-বাউন্ড) আর TTS (নেটওয়ার্ক/GPU) **একসাথে** চলে,
* Speed Governor প্রথম কয়েকটি ক্লিপের বাস্তব গতি মেপে ভবিষ্যৎ অনুমান করে;
  (IndicF5 ব্যবহার হলে) বাজেট ছাড়ানোর আশঙ্কায় diffusion ধাপ `nfe` নামায়,
* কাজ শেষে মডেল আনলোড করে **VRAM খালি** করা হয়।

## 🎤 ঐচ্ছিক: নিজের কণ্ঠে ডাবিং (voice cloning)

ডিফল্ট পথে **এটি দরকার নেই**। শুধু নিজের গলায় ডাবিং চাইলে:

1. **অনুমতি** — https://huggingface.co/ai4bharat/IndicF5-এ লগইন করে
   “Agree and access repository” চাপুন (একবারই)।
2. **HF token** — https://huggingface.co/settings/tokens (`read` যথেষ্ট)।
3. **অতিরিক্ত প্যাকেজ** — `pip install -r requirements-indicf5.txt`
4. **নমুনা** — `Video/input/`-এ ১০–২০ সেকেন্ডের পরিষ্কার বাংলা কথার
   `.wav/.mp3/.m4a` ফাইল রাখুন (৫s–১ মিনিট পর্যন্ত চলবে)।
5. **লগইন** (নোটবুকের ঐচ্ছিক সেল):

```python
from huggingface_hub import login
login(token="hf_...")
```

কিছু একটা না হলে অ্যাপ নিজেই বিল্ট-ইন ভয়েসে ফিরে যাবে — ভিডিও নষ্ট হবে না।
জোর করে শুধু ক্লোনিং চাইলে: `python main.py --tts-engine indicf5`; IndicF5 না
চললে ডিফল্টে (`tts.fallback_to_edge: true`) বিল্ট-ইন ভয়েসে ফিরে আসবে, আর
`false` করলে স্পষ্ট error দিয়ে থেমে যাবে।

## 🩺 সাধারণ সমস্যা ও সমাধান

| সমস্যা | সমাধান |
|---|---|
| `⏭️ আগের আউটপুট পাওয়া গেছে… বাদ দেওয়া হলো` | আগের রানের `video_bn.mp4` এখনো আছে। নতুন করে ডাবিং করতে `python main.py --force`, আর নোটবুকে ধাপ ৭-এ `FORCE_REPROCESS = True` (ডিফল্টেই `True`) |
| ধাপ ৮ চালানোর পর কিছুই দেখা যাচ্ছে না | এখন লগ লাইভ আসে (`python -u` + লাইন-বাইলাইন)। যদি একেবারেই কিছু না আসে: ধাপ ৪ (`pip install -r requirements.txt`) রান করুন — প্যাকেজ না থাকলে এখন সরাসরি `❌ প্রয়োজনীয় প্যাকেজ পাওয়া যায়নি: 'numpy'` বার্তা আসে |
| কোড পুরোনো দেখাচ্ছে (নতুন ফিচার নেই) | ধাপ ৩-এর সেল এখন `fetch` + প্রয়োজনে `reset --hard origin/main` করে **সর্বশেষ commit** এনে দেখায়; সেলটি আবার রান করুন |
| Gemini key দিইনি / ভুলে গেছি | চালু হওয়ার আগেই error দেখাবে: `Gemini API key পাওয়া যায়নি` → নোটবুকের ধাপ ৬-এ key পেস্ট করে আবার চালান |
| HF token দিইনি | কিছুই করতে হবে না — অ্যাপ নিজেই বিল্ট-ইন ভয়েসে চলে (এটা error নয়) |
| অডিও extract-এ ঝুলে যায় | আর অনন্তকাল ঝুলবে না; তবু হলে ভিডিওটি আবার আপলোড করুন (অর্ধেক আপলোড হওয়া ফাইল পড়া যায় না) |
| `Gemini API error (429 / quota)` | কিছুক্ষণ অপেক্ষা করুন — কোড নিজেই ৭ বার retry করে (প্রতিবার সর্বোচ্চ ২s অপেক্ষা); plan-এর limit দেখুন |
| `⚠️ উত্তর সঠিক ফরম্যাটে আসেনি` বারবার | এখনই স্বয়ংক্রিয়: ফরম্যাট ধাপে ধাপে সহজ হয়, কাটা উত্তর থেকে শুরুর লাইন রাখা হয়, অপেক্ষা ≤২s। লগে `🔀`/`♻️` দেখলে জানবেন এটি কাজ করছে |
| `edge-tts` ব্যর্থ / কণ্ঠ আসছে না | ইন্টারনেট সংযোগ দেখুন, `pip install -U edge-tts`; `tts.voice` বৈধ `bn-BD-*` কি না দেখুন |
| `CUDA out of memory` | Runtime → Restart; ক্লোনিং বন্ধ রাখলে (`auto` + নমুনা ছাড়া) GPU চাপ অনেক কম |
| `'ffmpeg' পাওয়া যায়নি` | `apt-get install -y ffmpeg` |
| ডাবিং ধীর | `--model medium` |
| নিজের কণ্ঠ ক্লোন হচ্ছে না | `Video/input`-এ নমুনা আছে কি না, HF অনুমতি/token ঠিক কি না দেখুন; অথবা `--tts-engine indicf5` দিয়ে সরাসরি চেষ্টা করুন |
| অনুবাদ ব্লক (`SAFETY`) | ওই অংশ বাদ যায়, বাকি ভিডিও চলতে থাকে; বাক্য পরিষ্কার করে আবার চালান |
